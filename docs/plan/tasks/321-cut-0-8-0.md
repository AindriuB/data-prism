## After the cut (each step needs its own owner go)
1. Push `release/0.8.0-cut`, open the release PR into `main`, CI green, merge with a merge commit.
2. **Gate: 263 Part B soak.** The owner runs `tasks/263-*.md` Part B on the merge commit, from a clean
   committed snapshot (`SOAK_ALLOW_DIRTY` unset): one node 8 h, three-member trusted-network cluster 4 h,
   with the faults, startup probes, captures and `LinkTimingSoakTest`; evidence in
   `docs/plan/perf/soak-0.8.md`. A defect found here goes back to a fix task and a re-cut; no tag before
   the evidence is recorded.
3. **Gate: Central File Count.** The owner records the choice (portal plan or limit checked; fewer modules;
   or at most one release a month) and confirms in the portal that this month's count leaves room for AC5's
   total. No dispatch before it is recorded.
4. Tag the merge commit `v0.8.0`, annotated, unsigned, message `Data Prism 0.8.0`.
5. Dispatch Central (`publish-central.yml --ref v0.8.0`, approve `central`, check the staged deployment,
   press Publish), then images (`publish-image.yml --ref v0.8.0 -f version=0.8.0`), then the MCP registry
   (`publish-mcp.yml --ref v0.8.0`) once `:0.8.0` is on GHCR.
6. Verify the release as `docs/verifying-releases.md` says; correct the CHANGELOG Build line and the page if a
   check fails, before any announcement.
7. Post-publish reruns against the published images, not the build overlay: a clean checkout's
   `docker compose up` (262); the `docs/quickstart.md` walkthrough capture; and
   `SMOKE_IMAGES=published docker/smoke/reidentification-smoke.sh`. Results go in the Outcome; a failure
   blocks the announcement.
8. Advisories: update GHSA-f94h-6mxv-c957 with patched version 0.8.0 and OD-290-2 (b)'s affected range and
   "no workaround"; publish GHSA-hcfg-rxg3-mgw6 alongside it. The Outcome carries the text for each.
9. AAR per the owner's rule for an `x.y.0` release, presented in chat, never committed.
