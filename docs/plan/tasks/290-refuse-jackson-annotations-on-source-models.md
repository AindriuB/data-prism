## Goal
After 288, a Jackson annotation on a source record does nothing: the engine reads each component itself. An author who wrote one expected it to change the output, so refuse it at startup with a message that names it and says what to do instead. Document the new source-model rule where the old allowance was documented, record the decision, and record in the CHANGELOG both the breaking change and the 0.7.x gap it closes.

## The rule
`SourceModels.require` (startup, through `DataPrismContractValidator`) refuses with `SOURCE_MODEL_JACKSON_ANNOTATION` any source model that carries a Jackson annotation not on the allowlist below, on:
- the record class, or an interface it implements;
- a component, as reflected on the component, its field, its accessor and the canonical constructor's parameter;
- any other method the record or its interfaces declare;
- an enum type reached from the model, or one of its constants.

A Jackson annotation is one whose type is in `com.fasterxml.jackson.annotation` or `tools.jackson.databind.annotation`, or is itself annotated `@JacksonAnnotationsInside`. The walk covers every record and enum the existing `walk` reaches. The message is `<Model.component>: @<Annotation> has no effect on a source model; remove it` (or `<Model>: ...` for the class), naming the annotation's simple name and never a value. The refusal replaces `refuseForeignProperties`, whose cases (`@JsonProperty` or `@JsonGetter` on a non-component method, `@JsonAppend`) it covers. Scrub time does not apply this rule: the walker already ignores the annotations.

**The allowlist (OD-290-1 (b), closed).** Exactly these pass, wherever the rule looks; every other Jackson annotation is refused:
- `@JsonAlias` (`com.fasterxml.jackson.annotation.JsonAlias`);
- `@JsonCreator` (`com.fasterxml.jackson.annotation.JsonCreator`);
- `@JsonDeserialize` (`tools.jackson.databind.annotation.JsonDeserialize`);
- `@JsonSetter` (`com.fasterxml.jackson.annotation.JsonSetter`);
- `@JsonIgnoreProperties` (`com.fasterxml.jackson.annotation.JsonIgnoreProperties`) only with `ignoreUnknown = true` and an empty `value`. With any name in `value`, or with `ignoreUnknown = false`, it is refused.

They affect only how an adapter reads the upstream response into the record (`RestDataSourceAdapter.java:86` reads the body straight into it, and 278's generated adapters will too), so they change nothing the walker writes. The allowlist is one constant in `SourceModels`, matched by annotation type, not by simple name; a custom annotation meta-annotated `@JacksonAnnotationsInside` is refused even when it bundles only allowed annotations, since the rule does not open it.

  > To fix a model refused with `SOURCE_MODEL_JACKSON_ANNOTATION`, remove the annotation the message names. From 0.8, Data Prism reads a source record itself: each component is written under its own name with its own value, and Jackson annotations on the record, its components, its methods and the enums it holds change nothing. If the annotation renamed a component in the output, rename the component. If `@JsonProperty` mapped an upstream response's name onto the component, use `@JsonAlias` for that name instead. If it changed how a value is written (`@JsonValue`, `@JsonSerialize`, `@JsonFormat`), give the component the type you want written: for a single sensitive value, a `String` with `@SensitiveData` instead of a record that serialises as one; for a formatted date, a `String` holding the text. If it hid a component (`@JsonIgnore`), remove the component or classify it. If it added keys to the object (`@JsonAnyGetter`), the keys can no longer sit beside the components: hold them in a named `Map<String, Object>` or `JsonNode` component. That component is never descended into. Classify it as a whole: unannotated or marked `@NonSensitive`, the profile's setting for unclassified data decides the whole value, and the bundled DEFAULT profile refuses it. If the keys must be handled one by one, serve that payload as a configured JSON source instead. `@JsonAlias`, `@JsonCreator`, `@JsonDeserialize`, `@JsonSetter` and `@JsonIgnoreProperties(ignoreUnknown = true)` stay allowed, because they affect only how an adapter reads the upstream response. To fix `SOURCE_MODEL_RECORD_NOT_DECLARED`, declare the position as the record type itself, not `Object`, an interface, `Record`, a type variable, an unbounded wildcard or a raw collection. To fix `SOURCE_MODEL_NOT_READABLE`, which can happen only on the module path, add an unqualified `opens` for the model's package to its `module-info.java`. To fix `SOURCE_MODEL_NOT_A_RECORD` on an `AtomicReference` or another reference type, hold the value itself, or an `Optional` of it. On a `Stream`, an `Iterator` or another single-use type, collect it into a `List` first. [OD-288-2 (a):] On a `Collections.unmodifiableList`, another wrapper or a map view, copy it with `List.copyOf`, `Set.copyOf` or `Map.copyOf`. To fix `SOURCE_MODEL_FOREIGN_NODE`, build the tree from Jackson's own node types and do not put a Java object into it (`putPOJO`).
