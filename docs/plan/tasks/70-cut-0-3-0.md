## Goal
Bump the reactor to 0.3.0, write the 0.3.0 changelog entry from the diffs that
actually landed, and leave no stale version literal anywhere a release attempt
would trip over it. Task 45's release cut established the checklist; follow it.

## Acceptance
- [ ] `rg --hidden -n '0\.2\.0'` over tracked files (excluding `docs/plan/` and
      `docs/plan/tasks/retired/`, which are history) returns only deliberate
      historical references — each one named in the commit body with why it stays.
- [ ] Root and every module pom read `0.3.0`; `mvn -q -DskipTests package` builds
      the reactor and produces jars whose filenames carry `0.3.0`.
- [ ] `server.json`'s `version` and its OCI package `identifier` tag both read
      `0.3.0`, and the file still carries no `registryBaseUrl` and no per-package
      `version` field.
- [ ] Both MCP `serverInfo` version literals read `0.3.0`, asserted by the existing
      tests that pin them.
- [ ] The four Dockerfiles and `publish-image.yml`'s `workflow_dispatch` default
      read `0.3.0`.
- [ ] `CHANGELOG.md` gains a `## [0.3.0]` entry written from the merged diffs of
      tasks 60-69, not from the task files' intentions. It names: one level of
      named nested catalogues in the configuration-driven connector and the new
      deeper-than-declared refusal code; the durable `FileAuditSink` behind
      `dataprism.audit.sink: hash-chained` with no rotation; the offline chain
      verifier and its stated inability to detect truncation of the most recent
      records; the audit-chain write-ordering fix; the widened bean-classification
      sweep; and the restored reviewed-adapter allow-list.
- [ ] No `CHANGELOG.md` sentence claims the audit log is tamper-proof, immutable or
      independently complete.
- [ ] The full reactor suite passes on the bumped tree, and the test count is
      recorded in the commit body against the commit it was measured on.
