## Goal
A Java developer should get a source adapter from one annotation and write no adapter class. On an `@LlmExposedModel` record, `@DataPrismSource(name = "loans", path = "/loans/{subject}")` means "GET this path and read this record". On a Spring HTTP interface (`@GetExchange` or `@PostExchange` returning the record), it means "call through this interface", which covers POST lookups, headers and query parameters. Either way the adapter is generated over Spring's `RestClient` from `dataprism.sources.<name>` (base URL, timeout and the existing transport settings), and it passes through the privacy engine like any other adapter.

- Decided at filing (low stakes):
  - **Discovery:** scan the application's auto-configuration packages (the `@SpringBootApplication` package and below), as Spring Data does for repositories. There is no annotation processor index and no new scan annotation.
  - **Record route:** `name` is required. `path` is required on a record, must contain exactly one `{subject}` segment, and must not set a scheme, host, query or fragment. The record must be an `@LlmExposedModel` record.
  - **Interface route:** `name` is required and `path` is not allowed. The interface declares exactly one HTTP exchange method. That method has exactly one parameter, which receives the subject id, and it returns the `@LlmExposedModel` record. Allowed parameter shapes (found in the external review of PR #162):
    - a `String` annotated `@PathVariable`, `@RequestParam` or `@RequestHeader`, which receives the subject id as is;
    - a `String` annotated `@RequestBody`, sent as the request body as is;
    - a record annotated `@RequestBody` with exactly one component, of type `String`. The adapter constructs it with the subject id through its canonical constructor, and Jackson serialises it. For example, `record LoanQuery(String loanId)` is sent as `{"loanId":"<subject>"}`.
    - Anything else refuses at startup with a coded refusal naming the interface and the method: another type, a record with zero, two or more components, a non-`String` component, an unannotated parameter, or a `Map` or `Object` body. `ResponseEntity`, `Optional` and reactive return types are refused, and so are default methods that call the exchange method.
  - **Package:** `connectors.rest.declared`.
- **Static headers: an allowlist (third external review of PR #162).** A denylist of credential names cannot be complete (`Ocp-Apim-Subscription-Key`, `X-Functions-Key` and `X-Access-Key` slipped past one), so static headers are allowlisted instead. Credentials go through `dataprism.sources.<name>.service-credential-reference` or `mtls`, never through a header in source code.
  - **Static header names.** A static header on the exchange annotation (`headers = ...`) or on the interface (`@HttpExchange(headers = ...)`) is accepted only if its name, compared case-insensitively and exactly, is one of: `Accept`, `Accept-Language`, `Content-Type`, `User-Agent`, `X-Client-Name`, `X-Client-Version`, `Api-Version`, `X-Api-Version`. The list is a constant in `connectors.rest.declared`, and its Javadoc gives the reason for each entry. Any other name refuses at startup with `SOURCE_HEADER_NOT_ALLOWED`, which replaces the proposed `SOURCE_CREDENTIAL_HEADER`: under an allowlist, the refusal says what was checked, not what the header is guessed to be. The message names the interface and the header, never the value.
  - **Static header values.** The value of an allowed static header is refused, with the same code, when it is a credential:
    - it starts (case-insensitive, after trimming, followed by a space or the end) with a known HTTP authentication scheme: `Basic`, `Bearer`, `Digest`, `Token`, `AWS4-HMAC-SHA256`, `Negotiate`, `NTLM`, `HOBA`, `Mutual`, `SCRAM-SHA-1`, `SCRAM-SHA-256`, `vapid`, `DPoP`, `ApiKey` or `Hawk`;
    - or it has the shape of a JWT (three dot-separated base64url parts, the first starting with `eyJ`).
  - **`@RequestHeader` parameter names.** These carry the subject id, so the static allowlist does not fit them. The name must end in `-Id` (case-insensitive). After splitting it on `-`, `_`, `.` and lower-to-upper case boundaries and lower-casing, no token may be one of: `authorization`, `auth`, `cookie`, `token`, `bearer`, `jwt`, `secret`, `password`, `passwd`, `session`, `credential`, `credentials`, `signature`, `apikey`, `key`, `subscription`, `access`. Anything else refuses with `SOURCE_HEADER_NOT_ALLOWED`. `X-Loan-Id` is accepted; `X-Session-Id` and `X-Access-Key-Id` are refused.
- Refusals: coded, at startup, naming the class and the source name and never a configured value. Examples: a missing `dataprism.sources.<name>`, a bad `path`, an interface of the wrong shape, two declarations with the same name, a declared name that clashes with a configured JSON source or a hand-written adapter. Use an existing code where the meaning matches (`INVALID_SOURCE_URL`, `INVALID_SOURCE_TIMEOUT`, `MISSING_SOURCE_ADAPTER`). Add at most three new codes, `SOURCE_HEADER_NOT_ALLOWED` included. 279 adds the hint and changes the exception type.

## Acceptance
- [ ] Tests are written first and fail on the base commit; the Outcome names them.
- [ ] Record route: an application with one annotated record and `dataprism.sources.loans.base-url` and `timeout` set calls `GET <base-url>/loans/<subject>` against an in-test HTTP server, and `get_entity_context` returns the record scrubbed under its annotations. A subject of `../../admin?x=1#f` reaches the server as one encoded path segment. A 404 gives the source a no-data status and no breaker failure.
- [ ] Interface route: an annotated interface with `@PostExchange("/loans/lookup")` taking `@RequestBody LoanQuery` (the subject id wrapped in a record), and one with `@GetExchange("/loans")` taking `@RequestParam("id") String`, each produce the request the interface declares, including a static non-credential header (`X-Client-Version`) from the exchange annotation. Each returns the scrubbed record. The `LoanQuery` body on the wire is exactly `{"loanId":"<subject>"}`.
- [ ] Parameter shapes: one test per allowed shape (`String` as a path variable, query parameter, header or body; a one-`String`-component record body), and one per refused shape: `Integer`; a two-component record; a record with one `Long` component; an unannotated `String`; a `Map<String,String>` body. Each refused shape gives its code, and the message names the interface and method and no value.
- [ ] Static headers, one table-driven test, each row run both as a header on the exchange annotation and on `@HttpExchange` at interface level.
  - **Accepted:** each allowlist entry, with a plain value (`Accept: application/json`, `X-Client-Version: 1.4.0`, and so on), in a different letter case from the constant.
  - **Refused by name, with `SOURCE_HEADER_NOT_ALLOWED`:**
    - `Authorization`, `Proxy-Authorization`, `X-Authorization`, `Cookie`;
    - `X-API-Key`, `Ocp-Apim-Subscription-Key`, `X-Functions-Key`, `X-Access-Key`;
    - `X-Custom-Flag`, and `Accept-Encoding` (not on the list).
  - **Refused by value, on an allowed name (`User-Agent`):** one row per scheme in the list (`Basic abc`, `Bearer abc`, `Digest username="a"`, `Token abc`, `AWS4-HMAC-SHA256 Credential=a`, `Negotiate abc`, ...), lower-case variants, and a JWT-shaped value. `User-Agent: Bearerless/1.0` and `User-Agent: Tokenizer/2` are accepted.
  - **`@RequestHeader` parameter names:** `X-Loan-Id` and `Loan-Id` are accepted; `X-Session-Id`, `X-Access-Key-Id`, `X-Loan` (no `-Id`) and `Authorization` are refused.
  - A sentinel header value never appears in a refusal message or the log.
  - **Mutation:** a substring instead of an exact-name comparison on the allowlist, and dropping the scheme check, each fail a row.
- [ ] Settings: one test per `dataprism.sources.<name>` setting (`timeout`, `mtls`, `service-credential-reference`) shows that it takes effect on the generated adapter, or that startup refuses with a code naming it. A slow server past `timeout` gives a timed-out source status.

- [ ] Generated adapters satisfy `@ConditionalOnBean(DataSourceAdapter.class)` with no other adapter present. They coexist with a configured JSON source and a hand-written adapter in one application (277's mixed harness), and each answers.
- [ ] Repository rule 1: `DeclaredSourcesArchitectureTest` shows that `connectors.rest.declared` has no dependency on `data-prism-mcp`, so a generated adapter can reach the MCP layer only through the orchestrator and the privacy engine.
- [ ] `data-prism-annotations` still has no non-JDK dependency (its existing guard passes).
- [ ] `docs/extending.md` opens with the `@DataPrismSource` section, giving both routes with a complete example each and every refusal code. It presents a hand-written `DataSourceAdapter` as the advanced route, and :46 states 275's grammar.
