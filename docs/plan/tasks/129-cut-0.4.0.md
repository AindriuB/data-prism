## Acceptance

1. The root and all module poms are at `0.4.0` (not SNAPSHOT). `git grep 0.4.0-SNAPSHOT`
   finds nothing outside `docs/plan/HISTORY.md` and `docs/plan/tasks/retired/`.
2. `DataPrismMcpServer` no longer hardcodes a version. Both `serverInfo` calls
   take the version from the build, e.g. a Maven-filtered resource or the jar
   manifest `Implementation-Version`. If the version cannot be read, they fall
   back to a fixed non-empty value such as `"unknown"` and never throw. One test
   asserts the reported version equals `project.version`, and it would have
   failed on the hardcoded `"0.3.1"`.
3. `server.json` (both version fields), the Dockerfile `ARG VERSION`, the
   `publish-image.yml` default and example, `QUICKSTART_IMAGE_TAG` examples, and
   local jar paths in README.md and docs say `0.4.0`.
4. Where the Central sentences say what is on Central, they now say the library
   modules are on Central at 0.4.0 and `data-prism-server` is not, per
   D-129(a). Remove "0.3.1 was not published there" style text, or turn it into
   history. Every remaining `0.3.1` or `0.3.0` hit outside PLAN/HISTORY/retired
   is classified in the return as historical or a deliberate pin.

   `[Unreleased]` above it only if that is the file's convention. Check the
   0.3.x sections. The section summarises what landed, from
   `docs/plan/HISTORY.md` entries for tasks 92–106 and 117–128; grep the
   HISTORY-INDEX rows. Group it Added / Changed / Security as the file does. It must carry:
