### Method for the 0.5.0 full package build (decided here)

**Resolve from a scratch file repository populated by `deploy`, never by
`install`.** The steps:

1. After step 3, run
   `mvn -B -DskipTests -DaltDeploymentRepository=scratch::file://<scratchpad>/repo-050 deploy`
   **without** `-Prelease`. The release profile swaps in
   `central-publishing-maven-plugin` (pom.xml:339-349), and that must not run.
2. Re-run the step 1 extraction with `data-prism.version` 0.5.0 and
   `-Dmaven.repo.local=<scratchpad>/m2-050`, a new empty directory. Supply a
   scratch `settings.xml` with `-s`. It declares `<scratchpad>/repo-050` as an
   extra repository, beside Central, for the Spring artifacts.
3. The snippet itself stays byte-for-byte unmodified.

Why this method:
- It exercises the actual 0.5.0 POM metadata that Central will serve: the
  parent POM, the BOM import, and the processor coordinates. It does so before
  publication, while a defect can still be fixed in this cut.
- `install` would put 0.5.0 into `~/.m2` and quietly shadow the Central
  artifacts in later checks.
- Deferring the build would leave the extending.md paragraph's claim
  unverified at the cut.

Repeating this build against Central after publication is an owner-gated
step listed below.
