## Amendment 2026-11-10 (owner, after review round 1)
**Decision P1: a declared marker type.** Review round 1 found that the `MISSING_SHARED_LINK_LIMITER` preflight (Preflights.java:212), a `BeanFactoryPostProcessor`, calls `factory.getBean(name, LinkAttemptLimiter.class)` to ask `clusterWide()`. That builds the application's limiter and its dependencies before any `BeanPostProcessor` exists, `ConfigurationPropertiesBindingPostProcessor` included: a limiter that injects `DataPrismProperties` gets an unbound copy (a false `MISSING_JWT_ISSUER`), and one that needs `PrivacyCluster` starts a Hazelcast member from unbound settings. The owner keeps the refusal before any singleton exists, so a refused member never joins the cluster; the preflight therefore judges from bean definitions only and never instantiates.
- **Marker.** `ClusterWideLinkAttemptLimiter extends LinkAttemptLimiter`, in `io.github.aindriub.dataprism.core.link` (data-prism-core), beside `LinkAttemptLimiter`. Added to Owns for that reason.
- **Preflight.** For each `LinkAttemptLimiter` bean name other than `LinkWiring.DEFAULT_LIMITER`, resolve the declared type with `factory.getType(name, false)`, which does not initialise the bean, and accept the bean only when that type is assignable to `ClusterWideLinkAttemptLimiter`. No `getBean` call, and no other call that can instantiate, remains in the preflight.
- **Fail closed.** A `null` (unresolvable) type, a type declared only as `LinkAttemptLimiter` (even if its `clusterWide()` would return `true`), or no application limiter bean at all, is refused. The message tells the application to declare its `@Bean` return type, or its class, as `ClusterWideLinkAttemptLimiter`, and names no value.
- **`clusterWide()` stays.** The marker overrides it as a default returning `true`; the startup decision reads the declared type only and never calls it. Reason: removing it is an SPI change outside this diff. It is declared at LinkAttemptLimiter.java:40-43 (core main, from 269, not yet in a release tag) and asserted by InMemoryLinkAttemptLimiterTest.java:250-265 (outside Owns), and the deferred brief 264 specifies it at lines 36 and 49. Inside this diff it is used only by Preflights.java (rewritten here), the LinkWiring.java:59 Javadoc and LinkAttemptLimiterConfigurationTest.java (both rewritten here). No other module, harness or integration test uses it.
- **Docs.** The `docs/configuration.md` limiter paragraph and the `dataprism.links` refusal row state the marker requirement in place of "`clusterWide()` is `true`".
- **Stale link.** Remove `{@link #dataPrismLinkLimiterValidated}` at LinkWiring.java:171; no such method exists after this change.
- **Bean count.** The marker adds no `@Bean` method. If the implementation changes the count, update `AutoConfiguredBeanInventoryTest` (now in Owns, count line only) to the new number.

## Amendment 2026-11-10 (owner, after review round 2)
**Decision P2: an application-supplied `PrivacyCluster` is treated as joining a cluster.** Review round 2 found that `LinkWiring.joinsCluster` (LinkWiring.java:88) reads only `dataprism.hazelcast.join.mode`. With `topology: embedded` and an application `PrivacyCluster` bean, the validator refuses every `join.*` setting (`CLUSTER_SETTINGS_IGNORED`, DataPrismPropertiesValidator.java:323-328), so `join.mode` is always unset there: the member is never refused and gets the per-member in-memory limiter, and a caller gets `invalid-attempt-limit` failed attempts on every member. That defeats OD-08-2 fallback (c) and the fail-closed rule. The owner refuses it, as on `tcp-ip` and `kubernetes`, and accepts the cost: an application whose own cluster is really one node must supply a `ClusterWideLinkAttemptLimiter` too.
- **Refusal condition.** `MISSING_SHARED_LINK_LIMITER` is raised when a consumer is active, `dataprism.hazelcast.topology` is `embedded`, no application limiter passes the P1 marker test, and either `join.mode` is `tcp-ip` or `kubernetes`, or the application supplies a `PrivacyCluster` (below). Both cluster tests live in LinkWiring.java; the supplied-cluster test takes the `ConfigurableListableBeanFactory`, so the preflight calls it with its `factory`.
- **Detection rule, definitions only.** Resolve `io.github.aindriub.dataprism.hazelcast.PrivacyCluster` by name with `ClassUtils.isPresent`/`forName` on the factory's class loader, as PropertiesValidation.java:59 and :75-86 do, so LinkWiring.java never loads the optional class. If the class is absent, no such bean can exist: not supplied. Otherwise the application supplies a cluster when some name from `factory.getBeanNamesForType(PrivacyCluster, true, false)` (manually registered singletons included) is not data-prism's own, judged by `ClusterBackedState.builtHere(factory, name)` (ClusterBackedState.java:116-128): it has a bean definition whose factory method is `dataPrismPrivacyCluster` on a factory bean whose class is `ClusterBackedState`. That is the bean at ClusterBackedState.java:58-59, `@ConditionalOnMissingBean` inside a class conditional on `HazelcastInstance` and `topology: embedded` (:46-47), so it is defined only when the application defines none. Ownership is by definition origin, never by bean name.
  No `getBean` call, nor any other call that can instantiate, is added. `ClusterBackedState.java` and PropertiesValidation.java are not edited: `builtHere` is called as is, and the type-name lookup is repeated in LinkWiring.java rather than shared, since PropertiesValidation.java is outside Owns.
- **Never refused.** `single-node`, and `embedded` with data-prism's own cluster on `join.mode: none` (no other `PrivacyCluster` definition), keep the in-memory limiter and are never refused for it.
- **Docs.** The `docs/configuration.md` limiter paragraph and the `dataprism.links` refusal row name the supplied-cluster case beside `tcp-ip` and `kubernetes`, and say that an application-supplied cluster needs a `ClusterWideLinkAttemptLimiter` even when it has one member.

## Amendment 2026-11-10 (owner, after full review at c478ac49)
**Owner decision 2026-11-10 (after full review at c478ac49): the link scans run in a surefire fork of their own.** Finding: `PiiLogScanTest`'s `LinkHttpRun` (PiiLogScanTest.java:1472) sets the JVM-wide `javax.net.ssl.trustStore` to its own self-signed JWKS certificate. `McpHttpEndToEndTest.java:118` sets a different one, and the integration-tests surefire config (`data-prism-integration-tests/pom.xml:100-113`) runs both classes in one fork. The JDK builds its default SSLContext once per JVM, so whichever boots second fails its JWKS fetch with PKIX, and every MCP call gets a 401. Decision: give the classes that use `LinkHttpRun` their own fork. Either a separate surefire execution for them, or `reuseForks=false` for the module if a separate execution can't isolate them. The owner accepts a slower integration-test run as the cost.

Owner decision 2026-11-10 (finding 236-2): resolvers are ordered by name, not by `@Order`. `KeyResolvers` (data-prism-orchestration, KeyResolvers.java:55) sorts the accepted resolvers by name, which makes the order deterministic. That module is outside Owns, and changing it would alter shipped behaviour. Beans are still collected with `orderedStream()`.
