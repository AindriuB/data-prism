## Goal
The first manual run of `supply-chain.yml` (run 39662563118, on `main`) failed on three CRITICAL advisories in `org.apache.tomcat.embed:tomcat-embed-core` 11.0.24, which Spring Boot 4.1.1 (the newest GA) manages: GHSA-9xv2-5v5q-p794 / CVE-2026-65905 (DIGEST authenticator capture-replay bypass), GHSA-gcx9-497g-6cp6 / CVE-2026-65182 (improper access control) and GHSA-h3x4-894j-xpx5 / CVE-2026-68525 (FORM authentication incorrect authorization). All three are fixed in 11.0.25. Every embedded-Tomcat artifact the reactor resolves must come out at 11.0.27, the newest 11.0.x on Central, with the override removable the moment Boot catches up. The fix ships whether or not Data Prism is exposed, and the Outcome records whether it was.

## Context

Each reaches Tomcat through `spring-boot-starter-webmvc` (`data-prism-server/pom.xml:43`, `data-prism-spring-boot-starter/pom.xml:46`, `data-prism-quickstart-fixtures/pom.xml:36`, `data-prism-quickstart-issuer/pom.xml:36`).
- **Pattern to follow.** `pom.xml:75-80` (the `jackson3.version` property, with a comment naming the GHSAs and the removal condition) and `pom.xml:102-117` (hazelcast and the `jackson-bom` import, declared ahead of the Spring Boot BOM import so they win).
- **A property alone does not work here.** The root pom has no `<parent>`; it imports `spring-boot-dependencies` in `<dependencyManagement>` (`pom.xml:~127-132`). An imported BOM's `${tomcat.version}` (`spring-boot-dependencies-4.1.1.pom:215`, `11.0.24`) is interpolated inside that BOM, so setting `tomcat.version` in this pom changes nothing on its own. That is why Jackson uses a BOM import and hazelcast an explicit entry. Do the same for Tomcat: define `tomcat.version` as `11.0.27`, then add one explicit managed `<dependency>` per Tomcat artifact that `dependency:tree` shows in any module, each with `<version>${tomcat.version}</version>`, ahead of the Boot import. At filing the local repository held `tomcat-embed-core`, `tomcat-embed-el` and `tomcat-embed-websocket`. Boot 4.1.1 also manages `tomcat-embed-jasper`, `tomcat-annotations-api`, `tomcat-jdbc` and `tomcat-jsp-api` (`spring-boot-dependencies-4.1.1.pom:3177-3209`); add any of those only if the tree shows it. If Central has an `org.apache.tomcat:tomcat-bom` at 11.0.27 that covers every artifact the tree shows, importing it in the `jackson-bom` position is acceptable instead; say which was chosen in the Outcome.
- **Comment text.** The property comment names the three GHSAs, says Spring Boot 4.1.1 manages 11.0.24, that they are fixed in 11.0.25, and ends "Remove this property and the Tomcat entries below when Spring Boot manages 11.0.25 or later." The `<dependencyManagement>` comment points back to it, as the `jackson-bom` comment does.
