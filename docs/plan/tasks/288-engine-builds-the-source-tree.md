## Goal
The scrubber applies a holding field's policy to whatever tree it is given and descends only into JSON objects. Today that tree is whatever Jackson writes, so any Jackson feature that changes the written shape (`@JsonValue`, a custom serializer, an array shape, an object id, a type wrapper, a `@JsonProperty` name swap) can move a sensitive value out from under its own classification. Make that impossible instead of detecting it: the engine walks the record itself, reading each component's value by its own rules and writing it under the component's own name, and hands only leaf values to Jackson.

## The walker (the rules `SourceTree.of(Object)` follows)
- **Root.** A `JsonNode` passes through as today: the result equals (`JsonNode.equals`) what `SourceTree.of` returns on the base commit. Any other root must be a record (`SOURCE_MODEL_NOT_A_RECORD` otherwise, as today); a record declaring type parameters is refused with `SOURCE_MODEL_GENERIC`.
- **Record.** An `ObjectNode` with one property per record component, in declaration order, named by the component's name, each value read from the component's private field (Decisions). No other property is written. Jackson annotations on the record, its components, accessors, other methods or interfaces have no effect (290 refuses them at startup for the author's sake, not for safety).
- **Position rule.** A non-null record value is accepted only where the declared type of its position, after unwrapping `Optional` and taking a collection's or array's element type, is exactly that record class. Anything else is refused with `SOURCE_MODEL_RECORD_NOT_DECLARED`: `Object`, an interface, `java.lang.Record`, a type variable, an unbounded wildcard, a raw collection, and a runtime class that differs from the declared one (heap pollution). A bounded wildcard is read by its upper bound; records are final, so `List<? extends Contact>` is exact. A record as a map value stays refused (`SOURCE_MODEL_MAP_OF_RECORD`).
- **Containers.** `Optional`, `OptionalInt`, `OptionalLong` and `OptionalDouble` are unwrapped, empty as `null` (D-173-1). A JDK `Collection` and an array other than `byte[]` and `char[]` become an `ArrayNode` in iteration order. A JDK `Map` becomes an `ObjectNode` whose keys are written as the reader writes that key type today; each key's runtime class passes `SourceModels.refuseKey`. A user subclass of a collection or map is refused (`SOURCE_MODEL_NOT_A_RECORD`), as `refuseContainer` does today.
- **Leaves.** A value whose class is on the existing `allowedLeaf` list (`SourceModels.java:372-381` on wave4) and is not read by getters is written by `READER.valueToTree`, so its text is what Jackson writes today. Enums are written by `name()`. A `JsonNode` component passes through. A delegated leaf must come back as a scalar, binary or null node; an object or array refuses with `SOURCE_MODEL_NOT_A_RECORD`. A platform class the reader would read by getters (a `Throwable`, `java.awt.Point`) is refused as today; the surviving part of `refuseSerializer` is that check, called directly.
- **Depth.** Nesting beyond 64 containers refuses with `TOO_DEEP` at `$`, so a self-containing `List<Object>` is refused rather than overflowing the stack. No fixture the scrubber accepts is refused by this bound.
- **Component-exact check (defence in depth, kept from 270).** After building each record node, the walker checks that its property names are exactly the record's component names. A failure refuses with `SOURCE_TREE_NOT_COMPONENT_EXACT`. It should never fire; a direct unit test of the check kills its mutants.
- **Refusal messages and paths.** A path names declared components only, uses `[*]` for indices and `<undeclared>` for map keys. A message names a class's simple name at most, never a value or a map key.
- **`SourceValues.prohibited` never throws for this task's refusals** (kept from 270). It reads the tree through a lenient mode of the same walker. Where `of` would refuse with `SOURCE_MODEL_RECORD_NOT_DECLARED`, `SOURCE_TREE_NOT_COMPONENT_EXACT` or `TOO_DEEP`, the lenient mode walks the value by its own runtime class and every scalar under it is prohibited. Where field access is denied, it reads through the accessors instead, which can only add prohibited values. The refusal then comes from `scrubber.scrub`, inside `DefaultContextOrchestrator.fetchAndScrub`'s per-source `try` (`:390` on wave4), so only that source is refused. `prohibited` is called outside that `try` (`:387`). Pre-existing refusals (`SOURCE_MODEL_NOT_A_RECORD`, `SOURCE_MODEL_GENERIC`) keep their behaviour.
- **Caching.** Field handles are cached per record class in a `ClassValue` or equivalent that keeps no class loader reachable beyond the class's own lifetime.

## OD-288-1 (open): `@JsonAnyGetter` open models
The walker ignores `@JsonAnyGetter`, and the owner's refusal list (290) refuses it. Today it is the only way a record source puts undeclared keys at the root of its tree. `docs/extending.md:364-366` documents it as allowed, and the undeclared-key tests use it in eight fixtures across four modules: `UndeclaredKeyRefusalTest`, `UndeclaredPropertyNameTest`, `UndeclaredKeyRefusalPathTest`, `UndeclaredKeyToolRefusalTest`, `UndeclaredKeyFixture`, `PerSourceHarness`, `AuditFieldDispositionTest` and `KeyShapeLeakScanTest`. Under the walker, the map is written as an ordinary component under its own name, so `$.<undeclared>` becomes `$.extra.<undeclared>`.
- **(a) Refuse it, as decided; migrate the fixtures.** Each fixture holds its extra keys in a `Map<String, Object>` component, and its expected paths gain the component's name. The undeclared-key rules stay covered: nested map keys and configured JSON sources (`ConfiguredJsonUndeclaredKeyRefusalTest`, unchanged) still reach them. Cost: an adopter's open root model must move its extra keys under a named component.
- **(b) Keep it, by the engine's own rule.** The walker flattens one `Map<String, ?>` component marked `@JsonAnyGetter` into its record's object, writing keys as for any map and refusing a key equal to a component name. 290 then exempts `@JsonAnyGetter` on such a component. Cost: the engine reads one Jackson annotation, and the collision rule is a new check to get right.
- **Recommendation: (a).** It is what the owner listed, it leaves no Jackson annotation with meaning, and the collision case (an extra key named like a `@NonSensitive` component) is a value swap that (a) cannot express at all. Today's behaviour on that collision is itself unchecked (270, Out of scope).
