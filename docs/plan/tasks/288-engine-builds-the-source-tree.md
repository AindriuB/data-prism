## Goal
The scrubber applies a holding field's policy to whatever tree it is given and descends only into JSON objects. Today that tree is whatever Jackson writes, so any Jackson feature that changes the written shape (`@JsonValue`, a custom serializer, an array shape, an object id, a type wrapper, a `@JsonProperty` name swap) can move a sensitive value out from under its own classification. Make that impossible instead of detecting it: the engine walks the record itself, reading each component's value by its own rules and writing it under the component's own name. Jackson is handed only JDK scalar values, never a value whose graph can hold a user class or a record.

## The walker (the rules `SourceTree.of(Object)` follows)
- **Root.** A `JsonNode` root is normalised (below). Any other root must be a record (`SOURCE_MODEL_NOT_A_RECORD` otherwise, as today).
- **Generic records first.** A record class that declares type parameters is refused with `SOURCE_MODEL_GENERIC` wherever it is met, before the position rule, so `SourceModelsTest`'s `Envelope` behind an `Object` component (:741-744) keeps its code.
- **Record.** An `ObjectNode` with one property per record component, in declaration order, named by the component's name, each value read from the component's private field (Decisions). No other property is written. Jackson annotations on the record, its components, accessors, other methods or interfaces have no effect (290 refuses them at startup for the author's sake, not for safety).
- **Unwrap order and declared types.** The walker carries the declared type of each position down from the component's generic type. At each level it applies, in this order: an `Optional`, `OptionalInt`, `OptionalLong` or `OptionalDouble` is unwrapped and its type argument becomes the declared type (empty is `null`, D-173-1); a JDK `Collection` or an array other than `byte[]` and `char[]` becomes an `ArrayNode` and its element type becomes the declared type of each element; a JDK `Map` becomes an `ObjectNode` and its value type the declared type of each value. So `List<Optional<Leaf>>` declares `Leaf` for each unwrapped element and is accepted, and `Optional<List<Leaf>>` and `Optional<Leaf[]>` likewise. A type variable or wildcard is read by its upper bound; an unbounded one, a raw type and `Object` declare nothing. A declared `Iterable<T>`, or a declared JDK interface that extends it (`Collection<T>`, `List<T>`, `Set<T>`, `Queue<T>`, `Deque<T>` and the like), is walkable by its type argument at startup, and at scrub time its runtime value is handled by its runtime class: a JDK `Collection` is walked with `T` as each element's declared type; any other runtime class goes through the leaf rule, so `Path` is a leaf and an `Iterable` Jackson writes as a container is refused. So `@NonSensitive Iterable<String> tags`, which starts today, still starts and still scrubs.
- **Position rule.** A non-null record value is accepted only where the declared type, after that unwrapping, is exactly that record class. Anything else is refused with `SOURCE_MODEL_RECORD_NOT_DECLARED`: `Object`, an interface, `java.lang.Record`, an unbounded type variable or wildcard, a raw collection, and a runtime class that differs from the declared one (heap pollution). Records are final, so `List<? extends Contact>` is exact. A record that is a map value is refused with `SOURCE_MODEL_MAP_OF_RECORD`, and a record at array level two or deeper (counted as `SourceModels.recordBeyondFirstArray` counts) with `SOURCE_MODEL_NESTED_COLLECTION_OF_RECORD`: the startup codes, now also at scrub time.
- **Containers.** A user subclass of a collection or map is refused (`SOURCE_MODEL_NOT_A_RECORD`), as `refuseContainer` does today. Map keys: each key's runtime class passes `SourceModels.refuseKey`; an enum key is written by `name()`, as enum values are; every other key is written as the reader writes that JDK key type today.
- **Reference and holder types.** Besides the four `Optional` types, which are unwrapped, every JDK reference or holder type is refused with `SOURCE_MODEL_NOT_A_RECORD`, at startup and at scrub time: `java.util.concurrent.atomic.AtomicReference`, `AtomicReferenceArray`, `AtomicStampedReference`, `AtomicMarkableReference`, `java.lang.ref.Reference` and its subclasses, `ThreadLocal`, `java.util.concurrent.Future`, and any other JDK class Jackson writes with a reference-type, bean, container or map serializer that the walker does not handle itself. `AtomicInteger`, `AtomicLong` and `AtomicBoolean` hold no object and are scalar leaves.
- **Single-use types (re-review P3).** `java.util.stream.BaseStream` and its subtypes, `Iterator`, `Spliterator` and `Enumeration` can be consumed only once. `SourceValues.prohibited` (`DefaultContextOrchestrator.java:387`) runs before `scrub` (:390), so if either read one, the other would get `IllegalStateException`, outside the per-source catch. These types are refused with `SOURCE_MODEL_NOT_A_RECORD` by type, at startup on the declared type and at scrub on the runtime class, before anything iterates or serializes them. The lenient walk records the position and does not touch the value.
- **Two readers (re-review P2).** Startup builds record serializers to inspect them: `SourceModels.walk` calls `SourceTree.refuseIfReadByGetters` on each record (`SourceModels.java:244`), and `refuseForeignProperties` reads a record's bean serializer until 290 replaces it. The parity oracle also needs Jackson's plain output. A guard that refuses records would break all three. So `SourceTree` builds two private readers from one shared configuration method. Both stay inside `SourceTree`, the class `ArchitectureTest.ONLY_DESIGNATED_CLASSES_CREATE_MAPPERS` (:108-117 on wave4) already allows, so that rule is unchanged.
  - **The leaf reader**, guarded (below). It is the only reader whose `valueToTree` main code calls, and only from the walker's leaf method.
  - **The inspecting reader**, unguarded. Main code uses it only to look serializers up (`refuseIfReadByGetters`, `refuseForeignProperties`, the leaf rule's container test); it never writes a value with it. The parity oracle reaches it through one package-private test seam, `referenceTree(Object)`, that no main class calls.
  - `SourceTreeReadersArchitectureTest` (ArchUnit) pins this:
    - no main class other than the walker calls the leaf method, and no main class calls `referenceTree`;
    - the inspecting reader's field is read only by `refuseIfReadByGetters`, the foreign-property lookup, the leaf rule's container test and `referenceTree`;
    - inside `SourceTree`, no serialising method of `ObjectMapper`, `ObjectWriter` or `SerializationContext` (`valueToTree`, `convertValue`, every `writeValue*`, `writeValueAsString` and `writeValueAsBytes` included, `writer()` or `writerFor()` followed by any `write*`, `serializeValue`) is called anywhere except in the leaf method, on the guarded reader, and in `referenceTree`.

    So the scrub path has no unguarded way to write a value. The test has negative fixtures for each forbidden call, so it cannot go blind to one.
- **Leaves.** Enums are written by `name()`. Any other value is a leaf, delegated to the leaf reader's `valueToTree`, only if all of these hold:
  - its class is loaded by the bootstrap or platform class loader, and is not a record, an enum, a collection, a map, an array other than `byte[]` and `char[]`, a reference or holder type, or a single-use type (above), and is not one the inspecting reader writes with a container, iterator or map serializer. So an `Iterable` that Jackson writes as a scalar, such as `java.nio.file.Path` (written as its URI text), is a leaf, and the guard and the scalar-result check still protect it;
  - it is not a class the reader would read by getters (`Throwable`, `java.awt.Point`): the surviving part of `refuseSerializer`, called directly;
  - the **leaf guard** passes. The leaf reader keeps a serializer modifier and an annotation introspector, the roles of today's `RecordsOnly` and `ClassLevelSerializers`, reduced to the leaf path: while a serializer is built for any class, they refuse every record, every class not loaded by the bootstrap or platform loader, every class-level serializer annotation, and every bean, reference-type or container serializer. So whatever a delegated value contains, Jackson can never write a user class or a record through it.
  - the result is a scalar, binary or null node; an object or array refuses with `SOURCE_MODEL_NOT_A_RECORD`.
- **One leaf rule (re-review P2).** `SourceModels.walk` at startup and the walker at scrub time call the same predicate for "may this class be a leaf", so a model that starts never fails every request on a leaf type, and a model refused at scrub time is refused at startup too, as far as the declared types say.
- **`tools.jackson` classes.** `allowedLeaf`'s name test (`c.getName().startsWith("tools.jackson.")`, `SourceModels.java:380` on wave4) is replaced by a code-source check: the class must come from the same code source as `tools.jackson.databind.JsonNode`, as `SourceTree.fromJacksonDatabind` already does for serializers. A class from there that is not a `JsonNode` is refused, not delegated.
- **`JsonNode` normalisation (root and components).** Every `JsonNode` the walker meets, at the root or in a component, map value or collection element, is checked in full before use. It may contain only Jackson's own container and scalar node classes, exactly: `ObjectNode`, `ArrayNode`, `StringNode`, the numeric nodes, `BooleanNode`, `NullNode` and `BinaryNode`, each from Jackson's code source and not a subclass. Anything else is refused with `SOURCE_MODEL_FOREIGN_NODE`: a `POJONode` whatever it holds, any other embedded-object node, a `MissingNode` inside a container, or a node class from outside Jackson, a subclass of a Jackson node class included. Otherwise the result equals (`JsonNode.equals`) what `SourceTree.of` returns on the base commit. `ConfiguredJsonScrubbingEngine`'s parsed trees contain only these classes, so configured JSON sources are unaffected.
- **Depth.** Nesting beyond 64 levels, where a record, a collection, an array, a map and a `JsonNode` container each count one, refuses with `TOO_DEEP` at `$`. So a self-containing `List<Object>` and a long `record Node(Node next)` chain are refused rather than overflowing the stack. No fixture the scrubber accepts is refused by this bound.
- **Component-exact check (defence in depth, kept from 270).** After building each record node, the walker checks that its property names are exactly the record's component names. A failure refuses with `SOURCE_TREE_NOT_COMPONENT_EXACT`. It should never fire; a direct unit test of the check kills its mutants.
- **Refusal messages and paths.** A path names declared components only, uses `[*]` for indices and `<undeclared>` for map keys. A message names a class's simple name at most, never a value or a map key.
- **Caching.** Field handles are cached per record class in a `ClassValue` or equivalent that keeps no class loader reachable beyond the class's own lifetime.

## `SourceValues.prohibited` (lenient walk)
`prohibited` never throws for this task's refusals (kept from 270). It runs outside `DefaultContextOrchestrator.fetchAndScrub`'s per-source `try` (`:387` on wave4); the refusal comes from `scrubber.scrub` inside it (`:390`), so only that source is refused. It reads the tree through a lenient mode of the same walker:
- Where `of` would refuse with `SOURCE_MODEL_RECORD_NOT_DECLARED`, `SOURCE_MODEL_MAP_OF_RECORD`, `SOURCE_MODEL_NESTED_COLLECTION_OF_RECORD`, `SOURCE_TREE_NOT_COMPONENT_EXACT` or `SOURCE_MODEL_FOREIGN_NODE`, it walks the value by its own runtime class, and every scalar under it is prohibited (a foreign node's own content is not read).
- **Unreadable records, the fail-closed rule.** Where field access is denied, every scalar reachable through the accessors is prohibited. That is not the whole set: with swapped accessors, a value held only in a field that no accessor returns is not reachable at all. `SourceModels.require` refuses an unreadable record class at startup, but only for the adapter's declared `responseType()` and the records it reaches. `SourceFanOut` does not check that a returned root record is of that declared type (corrected after the re-review of f7e30ac1). So an unreadable record can reach `prohibited` in two cases: an embedder skipped `require` (plain Java), or an adapter returned a different `@LlmExposedModel` record than it declared. The residual is exact. It needs all of: the module path, a model package not opened to `data-prism-core`, a root record class other than the declared one, and swapped explicit accessors. Its effect: a value held only in a field is missing from the prohibited set, so another source emitting the same raw value is not caught by `RawValueLeakValidator`. The refused source itself emits nothing. A root-type check fits neither `SourceTree` nor `SourceValues`, which do not know the declared type, and `SourceFanOut` is 246's. It is filed under Out of scope as a follow-up. `docs/extending.md` (290) states that plain-Java embedders must call `SourceModels.require`. The scrub of that source refuses with `SOURCE_MODEL_NOT_READABLE`, so the source's own output never carries the value. A readable record is always read by field, in the lenient walk as in `of`, so its every value is collected.
- **Bounded.** The lenient walk uses the same depth count as `of`, including record levels. At the bound it stops descending and returns what it has: the scrub of that source refuses with `TOO_DEEP`, so nothing under the bound is emitted by that source. It is iterative or bounded, never recursion without a limit, so no `StackOverflowError` can escape `prohibited`.
- **No refusal escapes (re-review P3).** `prohibited` throws for none of the walker's refusals, pre-existing ones included (`SOURCE_MODEL_NOT_A_RECORD`, `SOURCE_MODEL_GENERIC`). This resolves the follow-up 270 had left out of scope. For each refused position it records the position and prohibits every scalar under it that it can reach without serialising anything:
  - records by field, JDK containers and maps;
  - the content of a holder type, only from this closed allowlist, walked by the same rules:
    - `AtomicReference`, `AtomicReferenceArray`, `AtomicStampedReference` and `AtomicMarkableReference`, through their plain non-blocking getters;
    - `Optional`, `OptionalInt`, `OptionalLong` and `OptionalDouble`;
    - a Future only when its class is exactly `CompletableFuture`, `FutureTask` or `ForkJoinTask` (or a JDK subclass of one), loaded by the bootstrap or platform class loader, and `state() == Future.State.SUCCESS`, through `resultNow()`. A Future that is running, failed or cancelled is not read: no `get()`, no waiting, nothing that throws `CancellationException` or `ExecutionException`. A user class implementing `Future` is never read, not even `state()`, because the default `state()` calls `isDone()` and then `get()`, and a user `isDone()` can lie; its position is prohibited-unknown.
  
  Nothing else is read. That covers `ThreadLocal` (whose `get()` would read the orchestrator's own thread and could run a `withInitial` supplier), `java.lang.ref.Reference` and its subclasses (no `get()`, and nothing reconstructed through them), the internals of a user class, the content of a `POJONode`, and single-use values. Each such position is recorded as prohibited-unknown: nothing under it is added to the set, and the scrub of that source refuses inside the per-source `try`, so the source emits nothing. Every getter call on the allowlist is wrapped: a `RuntimeException` or `Error` other than `VirtualMachineError` from it is caught, and the position becomes prohibited-unknown. So nothing escapes `prohibited`, and it never blocks.

## OD-288-1: decided (a) by the owner, 2026-10-27 — `@JsonAnyGetter` open models
The walker ignores `@JsonAnyGetter`, and the owner's refusal list (290) refuses it. Today it is the only way a record source puts undeclared keys into its tree. `docs/extending.md:364-366` documents it as allowed, and nine fixtures in four modules use it: `UndeclaredKeyRefusalTest`, `UndeclaredPropertyNameTest`, `ScrubDispositionsTest` (`Open`, :58-59, used at :131-133), `UndeclaredKeyRefusalPathTest`, `UndeclaredKeyToolRefusalTest`, `UndeclaredKeyFixture`, `PerSourceHarness`, `AuditFieldDispositionTest` and `KeyShapeLeakScanTest`.

The facts (corrected 2026-10-27 after the internal review of 058d0f89): under the walker, the map is written as an ordinary component under its own name. The scrubber never descends into a `Map` component, because a `Map` is not `descendable` (`FieldMetadataResolver.java:35`). It takes the unclassified-structure path in `JsonTreeScrubbingEngine.scrubNestedObject` (:370-396 on wave4). So the keys never reach the undeclared-key handling (`UNKNOWN_FIELD`, `<undeclared-N>` placeholders, `$.<undeclared>` paths) at all:
- `extra` left unannotated: the scrub refuses with `UNDECLARED_FIELD` at `$.extra`;
- `extra` marked `@NonSensitive`: the profile's `unclassified` setting decides the whole map. Under DEFAULT it refuses with `UNCLASSIFIED_STRUCTURE`; a `REDACT` setting replaces the map with the marker; a pass-through setting releases the map whole, keys included.

For a record source, the undeclared-key handling becomes unreachable. It stays reachable through `JsonNode` roots: configured JSON sources, and a test resolver that exposes the tree.
- **(a) Refuse it; rework the fixtures. Decided.** Each of the nine either becomes a `JsonNode`-root source (with `ConfiguredJsonFieldMetadataResolver` or a test resolver that exposes the tree), so that its undeclared-key assertions still mean something, or keeps a record with a `Map<String, Object>` component and asserts the outcomes above instead. The Outcome says which for each. Cost: an adopter's open root model loses its extra keys' per-key handling. They must classify the holding map field as a whole, or move to a configured JSON source.
- **(b) Keep it, by the engine's own rule. Not chosen.** The walker flattens one `Map<String, ?>` component marked `@JsonAnyGetter` into its record's object, writing keys as for any map and refusing a key equal to a component name. The keys then reach the undeclared-key handling at the record's level, as today. 290 exempts `@JsonAnyGetter` on such a component. The nine fixtures pass unmodified. Cost: the engine reads one Jackson annotation, and the collision rule is a new check to get right.
- **Recommendation: (a).** It is what the owner listed, it leaves no Jackson annotation with meaning, and the collision case (an extra key named like a `@NonSensitive` component) is a value swap that (a) cannot express at all. Today's behaviour on that collision is itself unchecked (270, Out of scope).
- **Decided: (a), by the owner, 2026-10-27.**
