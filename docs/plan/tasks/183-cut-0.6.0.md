  Default: run it, with D-151-A's scratch `file://` deploy, because 0.6.0 is

  sources. A bad parent or BOM POM on Central cannot be withdrawn. In 0.5.0,
  auto mode denied local release steps, and the rebuild ran only after
  publication. If that happens again, the fallback is the same: defer it to
  the owner-gated post-publication list.
- **D-183-C, version strings for artifacts not yet published.** The
  `kubernetes.yaml` image tag, the `QUICKSTART_IMAGE_TAG` examples and the faq
  "latest release" sentence will say 0.6.0 before 0.6.0 exists on GHCR or
  Central. Default: accept, as D-151-D did.
- **D-183-D, CHANGELOG link style.** The file links each version to its
  release tag (`releases/tag/vX.Y.Z`) and has no `[Unreleased]:` or compare
  links. Default: keep that style and add only the `[0.6.0]` tag link.
  Switching to `compare/v0.5.0...v0.6.0` links, plus an `[Unreleased]`
  compare link, would mean rewriting every historical link. It would be a
  separate decision.
